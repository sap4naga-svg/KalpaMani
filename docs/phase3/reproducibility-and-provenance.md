# Phase 3 — Reproducibility and Provenance

**Status: PROPOSED — planning only. Nothing is implemented.**

---

## 1. The claim being made, and the claim being refused

> **No result is reproducible merely because the Python code is version-controlled.**

A commit SHA pins the *transformation*. It says nothing about the *inputs*, and in a
point-in-time system the inputs are the part that moves: vendors backfill, restatements
arrive, universes get rebuilt, lag policies get tuned. A backtest rerun six months later
against "the same code" will read a different world and produce a different number, and
without a manifest there is no way to tell that from a genuine regression.

Reproducible here means the strong version:

> **A recorded result can be regenerated byte-for-byte from its manifest alone, or the
> attempt fails loudly because an input it names no longer exists.**

Failing loudly is half the value. A silent re-derivation against changed data is how a
research programme accumulates results it cannot defend.

## 2. The research manifest

Emitted for every backtest, factor study, scanner run and dataset build. Stored beside the
result and immutable once written.

```yaml
manifest_version: 1
run_id: rs-3f9a2c81b04e7d16          # deterministic from the fields below

code:
  commit_sha: 210f768bb8763f78d4a02a70757f26c37457323e
  working_tree_clean: true           # false invalidates the run -- see §4
  config_version: research/2026.08.26.1

temporal:
  as_of_cutoff: 2026-06-30T20:00:00Z
  backtest_start: 2015-01-02
  backtest_end: 2026-06-30

datasets:
  - dataset_version: gold/2026.08.26.1
    layer: GOLD
    content_hash: sha256:2b1f...
    built_from_run_ids: [ing-9c14..., ing-77ab...]
  - dataset_version: silver/2026.08.25.3
    content_hash: sha256:c40e...

definitions:
  universe_definition_version: universe/v3
  corporate_action_version: ca/2026.08.26
  factor_definition_version: factors/v1
  lag_policy_version: lag/v2

lags_applied:                        # every approximation, named
  - domain: earnings_event
    rule: NEXT_SESSION_OPEN
    affected_rows: 41827
  - domain: corporate_action
    rule: ANNOUNCEMENT_PLUS_ONE_SESSION
    affected_rows: 9310

limitations:                         # see §3 -- this block is mandatory
  - ANALYST_REVISIONS_UNAVAILABLE
  - EARNINGS_TIME_APPROXIMATED
  - CLASSIFICATION_STATIC

quality:
  blocking_issues_open: 0            # non-zero => manifest is not emitted at all
  warnings_open: 14

execution:
  random_seed: 20260826
  engine: LEAN
  engine_version: "..."
  started_at: 2026-08-26T09:00:00Z
  completed_at: 2026-08-26T09:41:00Z

result:
  artifact_hash: sha256:8ae1...
```

`run_id` is **derived, not generated** — a hash over code commit, config version, dataset
versions, definitions, lag policy, `as_of` and seed. Same inputs, same id. This is the same
principle ADR-0004 §2 applied to order identity, for the same reason: *"No `uuid4()`. No
timestamps."* A derived id means two runs that claim to be the same run can be checked
against each other instead of merely asserted to match.

## 3. The `limitations` block is mandatory and load-bearing

Every manifest carries it, and an empty list is a positive claim that nothing was
approximated — not a default.

Defined values as of this plan:

| Token | Meaning |
|---|---|
| `ANALYST_REVISIONS_UNAVAILABLE` | Blueprint §6 revision sub-factor absent ([provider-evaluation.md](provider-evaluation.md) §2.8) |
| `EARNINGS_TIME_APPROXIMATED` | Announcement timing derived by lag, not verified |
| `BORROW_HISTORY_UNAVAILABLE` | **Any short exposure in this run is unqualified** |
| `CLASSIFICATION_STATIC` | Sector/industry not historised |
| `CORPORATE_ACTION_ANNOUNCE_APPROXIMATED` | Announcement date absent; lag applied |
| `CROSS_SOURCE_DISAGREEMENT_PRESENT` | Open §7 warnings on an input dataset |

Two enforcement rules:

- **A result carrying `BORROW_HISTORY_UNAVAILABLE` may not contain short positions.** The
  combination is refused at manifest emission, not caught in review. It is the mechanical
  form of the Phase-3C gate.
- **Any report, summary or claim derived from a manifest reproduces its `limitations`
  block.** A performance figure quoted without its limitations is quoted wrongly.

## 4. Preconditions for emitting a manifest

A manifest is refused — and therefore the result is not admissible — when:

1. The working tree is dirty. An uncommitted change is not reproducible by anyone else.
2. Any input dataset has an open `BLOCKING` quality issue
   ([data-quality-plan.md](data-quality-plan.md) §8).
3. Any dataset version named is unpublished or superseded.
4. Any content hash fails to verify against the artifact it names.
5. `as_of_cutoff` is absent, or later than the build time of any dataset used.
6. A short position appears in a run whose limitations include
   `BORROW_HISTORY_UNAVAILABLE`.

Refusing rather than warning is the same trade ADR-0004 made throughout: *"a halted system is
recoverable, a duplicated position is not."* Here, an unreproducible result that looks
reproducible is the unrecoverable one, because it will be cited later by someone who was not
in the room.

## 5. Strategy version and commit recorded with every trade

Blueprint §16 requires *"Strategy version + code commit recorded with every trade."* Phase 3
does not implement trading, but it establishes the vocabulary the later phases will record:
`code.commit_sha`, `definitions.factor_definition_version`, and the `dataset_version` set that
produced the signal.

**Proposed and deferred:** when Phase 4 generates signals, each carries the `run_id` of the
manifest that produced it, so a live trade is traceable to the exact dataset build behind its
signal. Recording that intention here means the schema does not have to be retrofitted under
time pressure later — the same reasoning that puts `model_version` and `prompt_version` in
`source_document` before any agent exists.

## 6. Retention

- Manifests are **retained permanently**, alongside Phase-1 and Phase-2 evidence, and are
  never edited.
- Bronze artifacts referenced by a published manifest are retained while that manifest is
  cited.
- Superseding a dataset version does not delete it; `superseded_by` records the successor.
- Manifests contain **no** brokerage account identifiers, account-binding digests, broker
  order ids or credentials (CLAUDE.md §3). Nothing in the research path has any reason to
  carry them, and the schema gives them nowhere to live.
